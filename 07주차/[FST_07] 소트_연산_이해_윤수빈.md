# 5장 소트 튜닝 
## 5.1 소트 연산에 대한 이해 
### 5.1.1 소트 수행 과정 
- 소트는 PGA에 할당한 Sort Area 에서 이뤄지고, 다 차면 디스크 Temp 테이블스페이스 활용
1. 메모리 소트 : 메모리 내에서 정렬 작업 완료
2. 디스크 소트 : 디스크 공간까지 사용하는 경우
- 디스크 소트가 발생하는 순간 SQL 성능은 나빠짐
- 소트는 부분범위 처리를 불가능하게 함으로써 OLTP 환경에서 애플리케이션 성능을 저하시키는 주요인임
=> 될 수 있으면 소트가 발생하지 않도록 쿼리 작성, 소트가 불가피하다면 메모리 내에서 수행을 완료할 수 있도록 해야함
### 5.1.2 소트 오퍼레이션
< 소트를 발생시키는 오퍼레이션 >
1. Sort Aggregate
   - 실제로 데이터를 정렬하진 않고, Sort Area를 사용함
   - 데이터를 정렬하지 않고 SUM, MAX, MIN, AVG 값 구하는 절차  
     1. Sort Area에 SUM, MAX, MIN, AVG 값을 위한 변수를 각각 하나씩 할당
     2. EMP 테이블 첫번째 레코드에서 읽은 SAL 값을 SUM, MAX, MIN, AVG 변수에 저장, COUNT변수에는 1을 저장
     3. EMP 테이블에서 레코드 하나씩 읽어 내려가면서 SUM 변수에는 값을 누적, MAX 변수에는 기존보다 큰 값이 나타나면 값 대체, MIN 도 동일, COUNT 변수에는 SAL 값이 NULL 이 아닌 레코드 만날 때마다 1씩 증가시킴
     4. EMP 레코드 다 읽으면 SUM, MAX, MIN 값은 변수에 담긴 값 그대로 출력, AVG는 SUM 값을 COUNT 로 나눈 값 출력
2. Sort Order By
   - 데이터 정렬 시 나타남
3. Sort Group By
   -  소팅 알고리즘 사용해 그룹별 집계를 수행할 때 나타남
   -  Sort Aggregate 방식 동일하게 사용 다만 그룹별로 동일하게 진행함
   -  집계할 대상 레코드가 아무리 많아도 Temp 테이블스페이스 쓰지 않음
   -  Hash Group By : 읽는 레코드 마다 Group By 컬럼의 해시 값으로 해시 버킷을 찾아 그룹별로 집계항목을 갱신하는 방식
     => 그룹 개수가 많지 않다면 레코드가 아무리 많아도 Temp 테이블스페이스 쓰지 않음
- 그룹핑 결과의 정렬 순서 : 정렬된 그룹핑 결과를 얻고자 한다면, 실행계획에 설령 'Sort Group By'라고 표시되더라도 반드시 Order By를 명시해야 함
4. Sort Unique
  Sort Unique 나타나는 경우 :  
    - Unnesting된 서브쿼리가 조인 컬럼에 Unique 인덱스가 없으면 메인 쿼리와 조인하기 전에 중복 레코드부터 제거해야함
    - 집합 연산자(Union, Minus, Intersect) 사용 시
    - Distinct 연산자 사용 시 => 오라클 10gR2부터는 Hash Unique 사용
  - PK/Unique 제약 or Unique 인덱스로 Unnesting 된 서브쿼리의 유일성이 보장된다면 Sort Unique 오퍼레이션 생략됨
5. Sort Join
  - 소트 머지 조인 수행 시 나타남
6. Window Sort
  - 윈도우 함수 수행 시 나타남
 
## 5.2 소트가 발생하지 않도록 SQL 작성
### 5.2.1 Union vs Union All
- Union All 은 중복을 확인하지 않고 두 집합을 단순히 결합하므로 소트 작업 수행 X
  => 될 수 있으면 Union All 사용
- Union 대신 Union All 사용해도 되는지 판단하려면 데이터 모델에 대한 이해와 집합적 사고 필요
- 두 집합이 상호배타적이라면 Union All을 사용해도 됨, 인스턴스 중복 가능성이 있다면 중복되지 않도록 쿼리변환이 필요
  
```
select 결제번호, 결제수단코드, 주문번호, 결제금액, 결제일자, 주문일자 ...
from 결제
where 결제일자 = '20180316'
UNION ALL
select 결제번호, 결제수단코드, 주문번호, 결제금액, 결제일자, 주문일자 ...
from 결제
where 주문일자 = '20180316'
and 결제일자 <> '20180316'   => 해당 줄 추가해서 Union All 함
```
### 5.2.2 Exists 활용
- Distinct 연산자의 경우 조건에 해당하는 데이터를 모두 읽어서 중복 제거해야 함 => 많은 I/O 발생
  => 이때 Exists 활용
- Exists 서브쿼리는 데이터 존재 여부만 확인하면 되기 때문에 조건절을 만족하는 데이터를 모두 읽지 않음
- Distinct, Minus 연산자 사용한 쿼리는 대부분 Exists 서브쿼리로 변환 가능
### 5.2.3 조인 방식 변경
- 적절한 경우에 해시 조인 => NL 조인으로 변경하면 소트 연산 생략 가능 
- 정렬 기준이 조인 키 컬럼이면 소트 머지 조인도 Sort Order By 연산을 생략 가능
